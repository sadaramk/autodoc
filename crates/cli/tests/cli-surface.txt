$ nunki --help
Verifiable, editorial architecture diagrams from source code

Usage: nunki <COMMAND>

Commands:
  init      Write an nunki.toml with editorial defaults into a repository
  analyze   Scan a repository: C4 containers, relationships, evidence, draft IR
  validate  Validate a DiagramIR file and print diagnostics (exit 1 on errors)
  render    Compile a DiagramIR into standalone HTML or SVG
  generate  Generate the architecture book: index.html, Markdown mirror, llms.txt, diagrams
  export    Export a diagram for another tool. One way: the source stays authoritative
  spec      Write the specification in another toolchain's format, from the code
  conform   Check the code against a specification someone else wrote
  diff      What changed architecturally between two revisions. Markdown for a PR comment
  check     Fail (exit 1) when the book is out of date or cites stale code. For CI
  verify    Verify evidence references like `src/main.rs:10-42`
  schema    Print the DiagramIR JSON Schema
  serve     Run the MCP server on stdio
  help      Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version

$ nunki export --help
Export a diagram for another tool. One way: the source stays authoritative

Usage: nunki export [OPTIONS] <IR>

Arguments:
  <IR>
          

Options:
      --format <FORMAT>
          Possible values:
          - drawio:     A draw.io file, carrying the book's layout: open it directly
          - drawio-csv: CSV for draw.io's Extras → Insert → Advanced → CSV, to merge into an existing drawing. draw.io routes the edges itself, so the result is laid out less well than the `drawio` file
          
          [default: drawio]

  -o, --output <OUTPUT>
          Output file. Defaults to the IR's name with the format's extension; `-` writes to stdout

      --repo <REPO>
          Repository the evidence belongs to, for permalinks. Defaults to the directory holding the IR, which for a generated book is inside it

  -h, --help
          Print help (see a summary with '-h')

$ nunki spec --help
Write the specification in another toolchain's format, from the code

Usage: nunki spec [OPTIONS] [PATH]

Arguments:
  [PATH]
          [default: .]

Options:
      --format <FORMAT>
          Dialect to write. `openspec` writes one current-state spec per capability, which `openspec validate --strict` will check

          Possible values:
          - openspec: `openspec/specs/<capability>/spec.md`, the current-state layout
          
          [default: openspec]

  -o, --out <OUT>
          Directory to write into. Defaults to the repository root, so the files land where the toolchain expects them

  -h, --help
          Print help (see a summary with '-h')
