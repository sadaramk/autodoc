autodoc

Architecture documentation generated from source code

autodoc reads a repository and writes an architecture book: diagrams chosen for the question they answer, an API reference, a data model, request and background flows, and a business-requirements scaffold. Every claim links to the file and line it came from, and each citation is verified against the commit.

What to look at first

  • Critical flows — sequence diagrams traced from a handler through its calls, writes and events, each message linked to the line that sends it.
  • API reference — parameters with their wire names and validation rules, request and response models, errors, and who calls each operation.
  • Data & integrations — the entity model with keys and cardinality, plus lifecycles read from status fields and the code that changes them.
  • Business requirements — what the code implements, with the intent it cannot know marked needs input rather than guessed.

Run it on your own repository

git clone https://github.com/sadaramk/autodoc
cd autodoc
cargo build --release -p autodoc-cli
./target/release/autodoc generate /path/to/your/repo --out docs/architecture
open docs/architecture/index.html

The book is self-contained and offline: one HTML file, a Markdown mirror for GitHub, llms.txt for agents, and the typed DiagramIR behind every figure, which you can edit by hand and keep.
